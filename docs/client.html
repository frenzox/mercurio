Rust client library

mercurio-client is an async MQTT client for Tokio, speaking MQTT 3.1, 3.1.1 and 5.0, with automatic reconnection.

Adding it

[dependencies]
mercurio-client = { git = "https://github.com/frenzox/mercurio" }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }

Connecting, publishing, subscribing

use mercurio_client::{ConnectOptions, Event, MqttClient, QoS};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let options = ConnectOptions::new("localhost", 1883).client_id("thermostat");
    let client = MqttClient::connect(options).await?;

    client.subscribe(&[("sensors/+/temperature", QoS::AtLeastOnce)]).await?;
    client.publish("sensors/hall/temperature", "20.5", QoS::AtLeastOnce).await?;

    while let Some(event) = client.recv().await {
        match event {
            Event::Message { topic, payload, .. } => {
                println!("{topic}: {}", String::from_utf8_lossy(&payload));
            }
            Event::Disconnected { reason } => eprintln!("disconnected: {reason:?}"),
            Event::Reconnected { .. } => eprintln!("reconnected"),
        }
    }
    Ok(())
}
  • publish and subscribe resolve once the broker acknowledged them: PUBACK, PUBCOMP or SUBACK.
  • recv returns the next event, and None once the client is closed for good.
  • Dropping the last handle disconnects normally, as disconnect does: the broker discards the will.
  • MqttClient methods take &self, so one client can be shared between tasks behind an Arc.

Connection options

ConnectOptions is a builder:

MethodMeaning
new(host, port)Broker address
unix(path)A broker on a Unix socket instead, such as its admin socket; no TLS. Unix only
client_id(id)Client id; the broker assigns one when not set
username(name), password(bytes)Credentials
protocol_version(v)ProtocolVersion::V5 (default), V3_1_1 or V3_1
keep_alive(seconds)Keep-alive, 60 by default
clean_start(bool), session_expiry(seconds)Start a new session or resume one, and how long the broker keeps it
will(Will)Message the broker publishes if the client disappears
reconnect(delay)Reconnect automatically after losing the connection
tls(true), ca_path(path)TLS, verified with the system's roots or the given CA
client_cert(cert, key)Authenticate with a client certificate
receive_maximum(n), maximum_packet_size(n), topic_alias_maximum(n)Limits announced to the broker
request_response_information(bool)Ask the broker for a response topic prefix, read with response_information()
authenticator(a)MQTT 5 enhanced authentication
connector(f)Open the stream with f instead of TCP
connect_timeout(seconds)Longest wait for the connection, 30 by default

The client follows the limits the broker announces in CONNACK, such as Maximum QoS, Receive Maximum, Maximum Packet Size and Retain Available, and holds the broker to the client's own.

The optional clap feature adds cli::ConnectArgs: the connection options recado and mercurioctl share, to flatten into your own clap command, and turned into ConnectOptions by to_connect_options().

Persistent sessions and reconnection

use std::time::Duration;
use mercurio_client::{ConnectOptions, MqttClient, Will};

let options = ConnectOptions::new("broker.example.com", 1883)
    .client_id("monitor")
    .clean_start(false)
    .session_expiry(3600)
    .reconnect(Duration::from_secs(5))
    .will(Will::new("status/monitor", "offline").retain(true));
let client = MqttClient::connect(options).await?;

When the connection drops, the client emits Event::Disconnected, retries every five seconds, and emits Event::Reconnected { session_present }. Messages not yet acknowledged are sent again. QoS 1 and 2 publishes made while disconnected wait and are sent after reconnecting; QoS 0 ones fail with ClientError::Disconnected. Without session_present, the broker forgot the session and the subscriptions have to be made again.

MQTT 5 properties

use mercurio_client::{MessageProperties, QoS};

let properties = MessageProperties {
    content_type: Some("application/json".into()),
    response_topic: Some("replies/thermostat".into()),
    correlation_data: Some("42".into()),
    message_expiry: Some(60),
    user_properties: vec![("source".into(), "hall".into())],
    ..Default::default()
};
client
    .publish_with_properties("requests/lamp", r#"{"on":true}"#, QoS::AtLeastOnce, false, properties)
    .await?;

Received messages carry their properties in Event::Message { properties, .. }, along with qos, retain and the subscription_ids they matched.

Subscription options

use mercurio_client::{QoS, RetainHandling, SubscriptionOptions};

let options = SubscriptionOptions {
    qos: QoS::AtLeastOnce,
    no_local: true,
    retain_as_pub: true,
    retain_handling: RetainHandling::DoNotSendRetained,
};
// Messages matching it carry subscription id 7
let results = client.subscribe_with(&[("chat/#", options)], Some(7)).await?;
assert!(results[0].success);

unsubscribe(&["chat/#"]) removes subscriptions; both return a result per filter with the broker's reason code.

Enhanced authentication

Implement Authenticator for a challenge-response method such as SCRAM. The exchange starts on every connection, reconnection and call to reauthenticate(). Authentication data is bytes::Bytes, from the bytes crate:

use bytes::Bytes;
use mercurio_client::Authenticator;

struct Token(String);

impl Authenticator for Token {
    fn method(&self) -> String {
        "TOKEN".into()
    }

    fn start(&mut self) -> Option<Bytes> {
        Some(Bytes::from(self.0.clone()))
    }

    fn respond(&mut self, _challenge: Option<Bytes>) -> Result<Option<Bytes>, String> {
        Err("TOKEN has no challenges".into())
    }
}

let options = ConnectOptions::new("localhost", 1883).authenticator(Token("secret".into()));

Errors and disconnections

Calls return ClientError, for example ConnectionRefused(reason), Redirected { server_reference, .. }, PublishRefused(reason) when the broker refuses a QoS 1 or 2 publish, Timeout, Tls(..) or Disconnected. Event::Disconnected says why the connection ended with a DisconnectReason: closed by the client, by the broker with a reason code, lost, or timed out.
