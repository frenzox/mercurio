Migrating from mosquitto

Mercurio reads mosquitto's password and ACL files as they are and publishes the same $SYS topics. This page maps each mosquitto option to its Mercurio equivalent.

Step by step

  1. Point password_file and acl_file at your existing files. Hashes written by mosquitto_passwd, $7$ and $6$, are recognised.
  2. Translate mosquitto.conf into TOML with the table below.
  3. Start mercuriod on another port, point a few clients at it, then move the rest.

Retained messages and persistent sessions are not imported from mosquitto's database; clients with persistent sessions start new ones, and retained messages need to be published again.

A typical configuration

mosquitto.confconfig.toml
listener 1883 127.0.0.1

listener 8883
certfile /etc/mosquitto/server.crt
keyfile /etc/mosquitto/server.key

allow_anonymous false
password_file /etc/mosquitto/passwd
acl_file /etc/mosquitto/acl

persistence true
persistence_location /var/lib/mosquitto/
 
[server]
host = "127.0.0.1"
port = 1883

[[listeners]]
host = "0.0.0.0"
port = 8883
[listeners.tls]
enabled = true
cert_path = "/etc/mosquitto/server.crt"
key_path = "/etc/mosquitto/server.key"

[auth]
enabled = true
allow_anonymous = false
password_file = "/etc/mosquitto/passwd"
acl_file = "/etc/mosquitto/acl"

[storage]
backend = "sqlite"
path = "/var/lib/mercurio/mercurio.db"

In mosquitto 2, per_listener_settings decides whether authentication is global or per listener. In Mercurio, [auth] applies everywhere, and a listener with its own [listeners.auth] uses that instead.

Differences to know

  • max_keepalive doesn't apply to MQTT 3.1.1 and 3.1 clients, as those protocols can't tell a client the server's limit. Mosquitto refuses them when they ask for a longer keep-alive, or for none; Mercurio accepts them with the keep-alive they asked for.
  • Mosquitto lets any client take over any client id. Mercurio refuses a client of another user, or on a listener with another mount point, with Not Authorized while the id has a session, and leaves that session alone. If a stale session blocks the new owner of an id, delete it with mercurioctl client delete-session <clientid> or wait for it to expire; see Client id ownership.
  • A bridge's local side is trusted: this broker's ACLs don't restrict what it forwards in.
  • Bridges to MQTT 3.1.1 brokers drop the remote broker's echo of what they forwarded, without mosquitto's try_private extension; see Bridges.
  • Over HTTP authentication, clientid is empty in login requests.
  • Dynamic security has no client or group priorities for roles; the ACL priority decides. It has no modifyClient, modifyGroup or modifyRole: change clients, groups and roles with the add, remove and set commands.
  • The answer to a $CONTROL request goes only to the client that sent it. Other clients subscribed to …/response don't see it.
