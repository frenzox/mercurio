Installing & running

Install a package or build the binaries, start the broker, and run it as a systemd service.

Packages

Each release of mercuriod, the broker, and recado, the command-line client, has .deb and .rpm packages and a plain .tar.gz for x86_64, aarch64 and armv7 Linux. They need glibc 2.18 or later. Download the one for your system and install it:

# Debian, Ubuntu, Raspberry Pi OS
sudo apt install ./mercuriod_*.deb ./recado_*.deb

# Fedora, RHEL, openSUSE
sudo dnf install ./mercuriod-*.rpm ./recado-*.rpm

The mercuriod packages install the broker as /usr/bin/mercuriod, the sample configuration as /etc/mercurio/config.toml and the systemd unit, and create a mercurio system user for the service. Edits to the configuration are kept across upgrades. The Debian package enables and starts the service. With the RPM, start it yourself:

sudo systemctl enable --now mercuriod

The service runs as mercurio, so files it reads that aren't readable by everyone, such as TLS keys and password files, must belong to that user or its group:

sudo chown root:mercurio /etc/mercurio/server.key
sudo chmod 640 /etc/mercurio/server.key

On armv7, WASM plugins run in wasmtime's interpreter, as its compiler doesn't support 32-bit ARM, so they're slower there.

Building

Mercurio needs a recent stable Rust toolchain. From the repository root:

# Broker, command-line client and libraries
cargo build --release

# Only the broker
cargo build --release --package mercuriod

# Or install the binaries into ~/.cargo/bin
cargo install --path mercuriod
cargo install --path recado

The binaries end up in target/release/: mercuriod, the broker, and recado, the command-line client.

Running the broker

mercuriod [OPTIONS]
mercuriod passwd -f <FILE> -u <USER> [-d]
mercuriod dynsec-init -f <FILE> [-u <USER>]
OptionMeaningDefault
-c, --config <FILE>Configuration file/etc/mercurio/config.toml
-l, --listen <ADDR>Override the main listen address, such as 0.0.0.0:1883from the configuration
-v, --verboseLog at debug level

Without a file at the default path, the broker starts with the defaults: plain MQTT on 127.0.0.1:1883, no authentication, state in memory. A missing file at a path given with -c is an error.

# Defaults
mercuriod

# Custom configuration, listening on every interface
mercuriod -c ./config.toml -l 0.0.0.0:1883

# Debug logging
mercuriod -v

Subcommands

CommandWhat it does
mercuriod passwd -f FILE -u USERAdds a user to a password file, or changes their password. Prompts for the password.
mercuriod passwd -f FILE -u USER -dRemoves a user.
mercuriod dynsec-init -f FILE [-u USER]Creates a dynamic security file with an administrator, admin by default.

Signals

SignalEffect
SIGTERM, Ctrl+CGraceful shutdown: every client is sent a DISCONNECT saying the server is shutting down, and the broker waits up to five seconds for connections to close.
SIGHUPRereads password files, ACL files and the dynamic security file, without dropping connections. See reloading.

A non-zero exit status means the broker failed to start, for example on an unusable TLS certificate or a port already in use, so service managers notice.

Running as a systemd service

A unit file is provided in mercuriod/contrib/mercuriod.service; the packages install it for you. It runs the broker sandboxed as the mercurio user, with /var/lib/mercurio as its only writable directory, which suits the SQLite database, and maps systemctl reload to SIGHUP. Without a mercurio user on the system, systemd creates a temporary one for each run.

# Binary, configuration and unit
sudo cp target/release/mercuriod /usr/bin/
sudo mkdir -p /etc/mercurio
sudo cp mercuriod/contrib/config.toml /etc/mercurio/
sudo cp mercuriod/contrib/mercuriod.service /etc/systemd/system/

# Start it now and at boot
sudo systemctl daemon-reload
sudo systemctl enable --now mercuriod

# Status, logs, reload
sudo systemctl status mercuriod
journalctl -u mercuriod -f
sudo systemctl reload mercuriod

The sample configuration lists every option with its default. A minimal production configuration that keeps state on disk and requires passwords:

[server]
host = "0.0.0.0"
port = 1883

[storage]
backend = "sqlite"
path = "/var/lib/mercurio/mercurio.db"

[auth]
enabled = true
allow_anonymous = false
password_file = "/etc/mercurio/passwd"
sudo mercuriod passwd -f /etc/mercurio/passwd -u alice
